# Vault Kubernetes Auth Setup Summary

## Overview
A complete HashiCorp Vault Kubernetes authentication setup has been added to the Pariksha Helm chart. This allows your Kubernetes workloads to authenticate to Vault securely using their ServiceAccount tokens.

## Files Created in `helm/templates/vault/`

### Core Vault Templates
1. **deployment.yaml** - Vault server deployment with proper security context and health checks
2. **service.yaml** - ClusterIP service exposing Vault API (port 8200) and cluster port (8201)
3. **configmap.yaml** - Vault configuration (vault.hcl) with storage and telemetry settings

### Kubernetes Authentication Setup
4. **serviceaccount.yaml** - Vault ServiceAccount for running the Vault pod
5. **clusterrole.yaml** - ClusterRole granting Vault permission to review tokens
6. **clusterrolebinding.yaml** - Binds the ClusterRole to Vault ServiceAccount

### Service ServiceAccounts
7. **service-accounts.yaml** - Pre-configured ServiceAccounts for:
   - auth
   - paper
   - question
   - exam
   - engine
   - gateway

### Initialization & Configuration
8. **k8s-auth-setup.yaml** - ConfigMap with setup scripts:
   - `setup-k8s-auth.sh` - Automates Kubernetes auth method configuration
   - `setup-secrets.sh` - Enables KV v2 and database secret engines

9. **vault-init-README.yaml** - Comprehensive documentation with:
   - Initial setup steps
   - Kubernetes auth configuration
   - Application integration examples
   - Troubleshooting guide
   - Production considerations

10. **init-job.yaml** - Optional Kubernetes Job to automatically initialize Vault

## Configuration in `helm/values.yaml`

Added Vault section with configurable options:
```yaml
vault:
  enabled: true
  replicaCount: 1
  image:
    repository: vault
    tag: "1.15.0"
  service:
    name: vault-service
    type: ClusterIP
    port: 8200
    targetPort: 8200
  clusterPort: 8201
  storage:
    type: "file"  # Can be "file" or "raft"
  secretPath: "pariksha"
  tls:
    disabled: true  # Set to false for production with certificates
```

## Quick Start

### 1. Deploy
```bash
helm install pariksha ./helm --set vault.enabled=true
```

### 2. Initialize Vault
```bash
kubectl port-forward -n pariksha svc/vault-service 8200:8200
vault operator init -key-shares=3 -key-threshold=2
vault operator unseal <KEY1>
vault operator unseal <KEY2>
vault login <ROOT_TOKEN>
```

### 3. Configure Kubernetes Auth
```bash
vault auth enable kubernetes
vault write auth/kubernetes/config \
  kubernetes_host=https://kubernetes.default.svc \
  kubernetes_ca_cert=@/run/secrets/kubernetes.io/serviceaccount/ca.crt \
  token_reviewer_jwt=@/run/secrets/kubernetes.io/serviceaccount/token
```

### 4. Create Policies and Roles
```bash
# Create policy
vault policy write service-policy - <<EOF
path "secret/data/pariksha/*" {
  capabilities = ["read", "list"]
}
EOF

# Create role for each service
vault write auth/kubernetes/role/auth \
  bound_service_account_names=auth \
  bound_service_account_namespaces=pariksha \
  policies=service-policy \
  ttl=24h
```

## Integration with Your Services

Each service (auth, paper, question, etc.) can authenticate to Vault:

```go
// In your service code
client, _ := api.NewClient(&api.Config{
    Address: "http://vault-service:8200",
})

auth, _ := kubernetes.NewKubernetesAuth("auth") // Use service name
secret, _ := client.Auth.Login(ctx, auth)

// Now use the authenticated client to fetch secrets
```

- Enable TLS for production
- Implement audit logging
- Regularly review and audit policies
- Consider Raft storage for HA in production
