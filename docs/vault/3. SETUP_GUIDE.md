# HashiCorp Vault Kubernetes Setup Guide

This document provides a comprehensive guide for setting up and using HashiCorp Vault in the Pariksha Kubernetes cluster with Kubernetes authentication.

## Architecture Overview

The Vault setup in this Helm chart includes:

- **Vault Server**: Runs as a StatelessSet pod with file-based storage
- **Kubernetes Auth Method**: Allows Kubernetes ServiceAccounts to authenticate to Vault
- **Multiple Service Accounts**: Pre-configured for auth, paper, question, exam, engine, and gateway services
- **RBAC Configuration**: ClusterRole and ClusterRoleBinding for Vault to access Kubernetes TokenReview API
- **ConfigMaps**: Contains Vault configuration and setup scripts

## Installation Steps

### 1. Deploy Vault with Helm

```bash
helm install pariksha ./helm \
  --namespace pariksha \
  --create-namespace \
  --set vault.enabled=true
```

### 2. Wait for Vault Pod to Be Ready

```bash
kubectl wait --for=condition=ready pod \
  -l app=vault \
  -n pariksha \
  --timeout=300s
```

### 3. Initialize Vault

Port-forward to Vault:
```bash
kubectl port-forward -n pariksha svc/vault-service 8200:8200 &
```

In another terminal, initialize Vault:
```bash
vault operator init \
  -key-shares=3 \
  -key-threshold=2

# Output will contain:
# - Unseal Keys (save these securely!)
# - Initial Root Token (save this securely!)
```

### 4. Unseal Vault

```bash
# Use at least key-threshold (2 in this example) unseal keys
vault operator unseal <UNSEAL_KEY_1>
vault operator unseal <UNSEAL_KEY_2>
```

### 5. Configure Vault

Login with the root token:
```bash
vault login <INITIAL_ROOT_TOKEN>
```

#### 5a. Enable KV v2 Secrets Engine

```bash
vault secrets enable -version=2 -path=secret kv
```

#### 5b. Enable Kubernetes Auth Method

```bash
vault auth enable kubernetes
```

#### 5c. Configure Kubernetes Auth

```bash
vault write auth/kubernetes/config \
  kubernetes_host=https://kubernetes.default.svc.cluster.local \
  kubernetes_ca_cert=@/run/secrets/kubernetes.io/serviceaccount/ca.crt \
  token_reviewer_jwt=@/run/secrets/kubernetes.io/serviceaccount/token
```

**Or use the setup script from the ConfigMap:**

```bash
# Extract the setup script
kubectl get cm vault-k8s-auth-setup -n pariksha \
  -o jsonpath='{.data.setup-k8s-auth\.sh}' > setup-k8s-auth.sh
chmod +x setup-k8s-auth.sh

# Run it
export VAULT_ADDR="http://localhost:8200"
export VAULT_TOKEN="<YOUR_ROOT_TOKEN>"
./setup-k8s-auth.sh
```

### 6. Create Policies for Services

#### Policy for Auth Service
```hcl
vault policy write auth-policy - <<EOF
path "secret/data/pariksha/auth/*" {
  capabilities = ["read", "list"]
}
path "secret/data/pariksha/shared/*" {
  capabilities = ["read", "list"]
}
path "database/static-creds/*" {
  capabilities = ["read"]
}
EOF
```

#### Generic Service Policy
```hcl
vault policy write service-policy - <<EOF
path "secret/data/pariksha/*" {
  capabilities = ["read", "list"]
}
path "database/static-creds/*" {
  capabilities = ["read"]
}
EOF
```

### 7. Create Kubernetes Auth Roles

For each service, create a Kubernetes auth role:

```bash
# Auth service
vault write auth/kubernetes/role/auth \
  bound_service_account_names=auth \
  bound_service_account_namespaces=pariksha \
  policies=auth-policy \
  ttl=24h

# Paper service
vault write auth/kubernetes/role/paper \
  bound_service_account_names=paper \
  bound_service_account_namespaces=pariksha \
  policies=service-policy \
  ttl=24h

# Question service
vault write auth/kubernetes/role/question \
  bound_service_account_names=question \
  bound_service_account_namespaces=pariksha \
  policies=service-policy \
  ttl=24h

# Exam service
vault write auth/kubernetes/role/exam \
  bound_service_account_names=exam \
  bound_service_account_namespaces=pariksha \
  policies=service-policy \
  ttl=24h

# Engine service
vault write auth/kubernetes/role/engine \
  bound_service_account_names=engine \
  bound_service_account_namespaces=pariksha \
  policies=service-policy \
  ttl=24h

# Gateway service
vault write auth/kubernetes/role/gateway \
  bound_service_account_names=gateway \
  bound_service_account_namespaces=pariksha \
  policies=service-policy \
  ttl=24h
```

### 8. Store Secrets in Vault

Example: Store database credentials
```bash
vault kv put secret/pariksha/auth \
  db_password="your-secure-password" \
  db_user="auth_user"

vault kv put secret/pariksha/paper \
  db_password="your-secure-password" \
  db_user="paper_user"
```

## Using Vault in Your Applications

### Go Example

```go
package main

import (
    "context"
    "log"

    "github.com/hashicorp/vault/api"
    "github.com/hashicorp/vault/api/auth/kubernetes"
)

func main() {
    client, err := api.NewClient(&api.Config{
        Address: "http://vault-service:8200",
    })
    if err != nil {
        log.Fatalf("Unable to initialize Vault client: %v", err)
    }

    // Authenticate using Kubernetes auth
    k8sAuth, err := kubernetes.NewKubernetesAuth("auth") // role name
    if err != nil {
        log.Fatalf("Unable to initialize Kubernetes auth method: %v", err)
    }

    authInfo, err := client.Auth.Login(context.Background(), k8sAuth)
    if err != nil {
        log.Fatalf("Unable to login with Kubernetes auth: %v", err)
    }

    // Use the token
    token := authInfo.Auth.ClientToken
    client.SetToken(token)

    // Read secrets
    secret, err := client.KVv2("secret").Get(context.Background(), "pariksha/auth")
    if err != nil {
        log.Fatalf("Unable to read secret: %v", err)
    }

    data := secret.Data["data"].(map[string]interface{})
    dbPassword := data["db_password"].(string)
    
    // Use credentials...
}
```

### Kubernetes Service Account Configuration

Update your deployment to use the service account:

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: auth-deployment
spec:
  template:
    spec:
      serviceAccountName: auth  # Must match the Kubernetes auth role
      containers:
        - name: auth
          image: auth_service:latest
          env:
            - name: VAULT_ADDR
              value: "http://vault-service:8200"
```

## External Secrets Operator Integration

If you're using External Secrets Operator, create a SecretStore:

```yaml
apiVersion: external-secrets.io/v1beta1
kind: SecretStore
metadata:
  name: vault
  namespace: pariksha
spec:
  provider:
    vault:
      server: "http://vault-service:8200"
      path: "secret"
      version: "v2"
      auth:
        kubernetes:
          mountPath: "kubernetes"
          role: "default-service"
```

Then create ExternalSecrets:

```yaml
apiVersion: external-secrets.io/v1beta1
kind: ExternalSecret
metadata:
  name: auth-secrets
  namespace: pariksha
spec:
  secretStoreRef:
    name: vault
    kind: SecretStore
  target:
    name: auth-secret
    creationPolicy: Owner
  data:
    - secretKey: db-password
      remoteRef:
        key: pariksha/auth
        property: db_password
    - secretKey: db-user
      remoteRef:
        key: pariksha/auth
        property: db_user
```

## Troubleshooting

### Check Vault Status
```bash
kubectl exec -it -n pariksha deployment/vault-deployment -- vault status
```

### View Kubernetes Auth Configuration
```bash
kubectl exec -it -n pariksha deployment/vault-deployment -- \
  vault read auth/kubernetes/config
```

### View Kubernetes Auth Roles
```bash
kubectl exec -it -n pariksha deployment/vault-deployment -- \
  vault list auth/kubernetes/role
```

### Test Authentication
```bash
# Get the JWT from a pod's service account
kubectl exec -it -n pariksha <POD_NAME> -- \
  cat /var/run/secrets/kubernetes.io/serviceaccount/token

# Try to login (from within the pod or with the token)
curl -X POST http://vault-service:8200/v1/auth/kubernetes/login \
  -d '{"role":"auth","jwt":"<TOKEN>"}'
```

### View Vault Logs
```bash
kubectl logs -n pariksha deployment/vault-deployment
```

## Security Considerations

1. **Unseal Keys**: Store unseal keys in a secure location, ideally using a KMS
2. **Root Token**: Revoke the root token after initial setup
3. **TLS**: Enable TLS for production deployments (set `vault.tls.disabled: false`)
4. **Audit Logging**: Enable audit logs for compliance
5. **Backup**: Implement regular backups of the Vault database
6. **HA Setup**: For production, use Raft storage with multiple replicas
7. **RBAC**: Regularly review and minimize policy permissions

## Production Recommendations

1. Use **Raft** storage backend for HA:
   ```yaml
   vault:
     storage:
       type: "raft"
   ```

2. Enable **TLS**:
   ```yaml
   vault:
     tls:
       disabled: false
   ```

3. Use **Auto-Unseal** with cloud KMS

4. Enable **Audit Logging**

5. Configure **Replication** for disaster recovery

6. Set up **Monitoring** and **Alerting**
