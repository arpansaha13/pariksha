## 📋 Configuration Summary

### Helm Values Added

```yaml
vault:
  enabled: true
  replicaCount: 1
  image:
    repository: vault
    tag: "1.15.0"
  service:
    name: vault-service
    type: ClusterIP
    port: 8200
    targetPort: 8200
  clusterPort: 8201
  storage:
    type: "file"
  secretPath: "pariksha"
  tls:
    disabled: true
```

### Deploy Command

```bash
helm install pariksha ./helm \
  --namespace pariksha \
  --create-namespace \
  --set vault.enabled=true
```

## 🔗 Service Accounts Created

The following ServiceAccounts are automatically created and can be used by your services:

```
auth      → Vault role: auth       → Policy: auth-policy
paper     → Vault role: paper      → Policy: service-policy
question  → Vault role: question   → Policy: service-policy
exam      → Vault role: exam       → Policy: service-policy
engine    → Vault role: engine     → Policy: service-policy
gateway   → Vault role: gateway    → Policy: service-policy
```

Each service can authenticate using its ServiceAccount and will have access to:
- Its own secrets at `secret/pariksha/<service-name>`
- Shared secrets at `secret/pariksha/shared`
- Database credentials at `database/static-creds/*` (when configured)

## 🆘 Quick Troubleshooting

### Vault pod not starting?
```bash
kubectl logs -n pariksha deployment/vault-deployment
```

### Can't connect to Vault?
```bash
kubectl port-forward -n pariksha svc/vault-service 8200:8200
```

### Kubernetes auth not working?
```bash
# Check configuration
vault read auth/kubernetes/config
```

For more troubleshooting, see **VAULT_SETUP_GUIDE.md** or **VAULT_README.md**

## 📊 Architecture Overview

```
Services (auth, paper, question, etc.)
         ↓
Read JWT Token
         ↓
Send to Vault /auth/kubernetes/login
         ↓
Vault verifies with Kubernetes API
         ↓
Issue Client Token
         ↓
Access Secrets at secret/pariksha/service-name
         ↓
Database Credentials, API Keys, etc.
```
