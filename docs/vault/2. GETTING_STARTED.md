## Overview

A complete HashiCorp Vault setup has been integrated into the Pariksha Helm chart, providing:

- **Kubernetes Native Authentication**: Services authenticate using their Kubernetes ServiceAccount tokens
- **Secrets Management**: Centralized storage and management of application secrets
- **Dynamic Credentials**: Support for database dynamic credentials (future enhancement)
- **Audit Logging**: Track all access to secrets
- **High Availability**: Ready for raft-based clustering

### Why Vault?

✅ **Zero-Trust Security**: Secrets are never stored in ConfigMaps or environment variables
✅ **Dynamic Secrets**: Generate database credentials on demand
✅ **Encryption**: All secrets encrypted at rest and in transit
✅ **Auditability**: Complete audit trail of all secret access
✅ **Multi-Cloud Ready**: Works across any Kubernetes distribution

### Authentication Flow

```
1. Pod (with service account "auth") starts
   ↓
2. Reads JWT token from /var/run/secrets/kubernetes.io/serviceaccount/token
   ↓
3. Sends request to Vault: POST /v1/auth/kubernetes/login
   ├─ role: "auth"
   └─ jwt: <TOKEN_CONTENT>
   ↓
4. Vault's Kubernetes Auth Method:
   ├─ Calls Kubernetes TokenReview API
   ├─ Verifies JWT signature
   ├─ Checks ServiceAccount name matches binding
   └─ Checks namespace matches binding
   ↓
5. Vault returns client token with attached policies
   ↓
6. Pod uses token to access secrets at path "secret/data/pariksha/*"
```

## Quick Start

### 1. Deploy Vault

```bash
# Install the Pariksha Helm chart with Vault enabled
helm install pariksha ./helm \
  --namespace pariksha \
  --create-namespace \
  --set vault.enabled=true

# Wait for Vault pod to be ready
kubectl wait --for=condition=ready pod \
  -l app=vault \
  -n pariksha \
  --timeout=300s
```

### 2. Initialize Vault

```bash
# Port-forward to Vault
kubectl port-forward -n pariksha svc/vault-service 8200:8200 &

# Initialize (in another terminal)
vault operator init \
  -key-shares=3 \
  -key-threshold=2

# SAVE the output! You'll need the unseal keys and root token!
```

### 3. Unseal Vault

```bash
# Unseal with at least key-threshold unseal keys
vault operator unseal <UNSEAL_KEY_1>
vault operator unseal <UNSEAL_KEY_2>
```

### 4. Quick Configuration

```bash
# Login as root
vault login <ROOT_TOKEN>

# Enable Kubernetes auth
vault auth enable kubernetes

# Configure it
vault write auth/kubernetes/config \
  kubernetes_host=https://kubernetes.default.svc \
  kubernetes_ca_cert=@/run/secrets/kubernetes.io/serviceaccount/ca.crt \
  token_reviewer_jwt=@/run/secrets/kubernetes.io/serviceaccount/token

# Enable KV v2
vault secrets enable -version=2 -path=secret kv

# Done! Your Vault is ready.
```

## Integration Guide

### For Go Services

See **`VAULT_INTEGRATION_EXAMPLES.md`** for complete code examples including:

1. **Vault Client Wrapper**
   ```go
   client, _ := vault.NewClient(ctx, "http://vault-service:8200", "auth")
   secret, _ := client.GetSecretString(ctx, "pariksha/auth", "db_password")
   ```

2. **Kubernetes Deployment Updates**
   ```yaml
   spec:
     serviceAccountName: auth  # Must match K8s auth role
   ```

3. **Token Management**
   - Token renewal
   - Error handling
   - Testing with mocks

### Kubernetes Deployment Template Update

Update your service deployments to use the service account:

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: auth-deployment
spec:
  template:
    spec:
      serviceAccountName: auth  # IMPORTANT: Must match Vault role name
      containers:
        - name: auth
          image: auth_service:latest
          env:
            - name: VAULT_ADDR
              value: "http://vault-service:8200"
```

### Add Secrets to Vault

```bash
# Store database credentials
vault kv put secret/pariksha/auth \
  db_user="auth_user" \
  db_password="secure_password"

# Store other service secrets
vault kv put secret/pariksha/paper \
  db_user="paper_user" \
  db_password="secure_password"
```

### Create Kubernetes Auth Roles

```bash
# For each service
vault write auth/kubernetes/role/auth \
  bound_service_account_names=auth \
  bound_service_account_namespaces=pariksha \
  policies=service-policy \
  ttl=24h
```

## Configuration Reference

### Helm Values

```yaml
vault:
  enabled: true                    # Enable/disable Vault
  replicaCount: 1                  # Number of replicas (1 for dev, 3+ for HA)
  image:
    repository: vault              # Vault image
    tag: "1.15.0"                  # Vault version
  service:
    name: vault-service
    type: ClusterIP                # or LoadBalancer for external access
    port: 8200
    targetPort: 8200
  clusterPort: 8201                # For Vault raft clustering
  nodeID: "vault-0"
  logLevel: "info"
  storage:
    type: "file"                   # "file" or "raft"
  secretPath: "pariksha"           # Base path for application secrets
  tls:
    disabled: true                 # Set to false for production with certs
  resources: {}                    # Resource limits
```

### Storage Options

**File Storage** (Development)
```yaml
storage:
  type: "file"
```
- Simple, single-node setup
- Data stored in `/vault/file`
- No HA capabilities

**Raft Storage** (Production HA)
```yaml
storage:
  type: "raft"
```
- Distributed consensus
- Automatic failover
- Multiple replicas

## Troubleshooting

### Common Issues

**Issue**: "Vault is sealed"
```bash
# Unseal with multiple keys
vault operator unseal <KEY1>
vault operator unseal <KEY2>
```

**Issue**: "Permission denied" when accessing secrets
```bash
# Check policy
vault read auth/kubernetes/role/auth

# Verify policy
vault policy read service-policy
```

**Issue**: Kubernetes auth not working
```bash
# Check K8s auth configuration
vault read auth/kubernetes/config

# Verify service account token
kubectl get secret $(kubectl get secret -n pariksha | grep auth-token | awk '{print $1}') -n pariksha -o jsonpath='{.data.token}' | base64 -d | jq
```

### Debug Commands

```bash
# Check Vault status
vault status

# List auth methods
vault auth list

# List secret engines
vault secrets list

# View all policies
vault policy list

# Test Kubernetes auth
curl -X POST http://localhost:8200/v1/auth/kubernetes/login \
  -d '{"role":"auth","jwt":"<TOKEN>"}'
```

## Security

### Best Practices

1. **Never commit unseal keys to git**
   ```bash
   # After init, save keys securely (KMS, password manager, HSM)
   # Delete from temporary files
   shred -u unseal_keys.txt
   ```

2. **Revoke root token after setup**
   ```bash
   vault token revoke -self
   ```

3. **Enable TLS in production**
   ```yaml
   vault:
     tls:
       disabled: false
   ```

4. **Use Raft storage for HA**
   ```yaml
   vault:
     storage:
       type: "raft"
   ```

5. **Enable audit logging**
   ```bash
   vault audit enable file file_path=/vault/logs/audit.log
   ```

6. **Implement token rotation**
   - Use short TTLs (24h for example)
   - Implement automatic renewal in applications

7. **Least privilege policies**
   ```hcl
   # Good: Specific path
   path "secret/data/pariksha/auth/*" {
     capabilities = ["read"]
   }

   # Bad: Too permissive
   path "secret/data/*" {
     capabilities = ["read", "create", "update", "delete"]
   }
   ```

### Production Checklist

- [ ] Use external identity provider for initial auth (not root token)
- [ ] Enable TLS with valid certificates
- [ ] Use Raft storage for HA
- [ ] Set up off-site backup
- [ ] Enable audit logging
- [ ] Configure monitoring and alerts
- [ ] Implement KMS-based auto-unseal
- [ ] Document all policies
- [ ] Regular security audits
- [ ] Disaster recovery testing
